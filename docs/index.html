The notch, put to work

You hand a task to Claude Code, switch to something else, and come back twenty minutes later to find it's been waiting for a yes since minute two. Visor fixes that. It turns the black strip at the top of your MacBook into a small control room for your AI agents: who's working, who needs you, and how much of your plan is left.

A sliver of black that knows who needs you

Closed, Visor is barely there: a little black on each side of the notch. That's enough to tell you everything that matters without opening a thing. Busy agents pulse on the left. When one needs you, the app it's running in appears on the right with a badge: amber to approve, blue to answer. Finished turns get a green check, and peeks say when two agents edit the same file, an agent is stuck, a Claude limit is about to run out or a tool is having an incident.

Hover, and it opens. Move away, and it's gone.

Claude Code, Copilot CLI and Antigravity CLI.
Tab 1 of 5

Agents

Who is working, who needs you, and what they did. Approvals, finished turns, helpers and clashes all land here, as a list or an office.

Every agent, in one list

Three terminals, two editors, and you've lost track of who's doing what. The Agents tab lists every running session, grouped by agent, with what it's doing right now: "Bash: npm test", "Edit: README.md". Click one and the app it runs in comes forward. Restart Visor and the list is still there.

Sessions sit two to a row. Each Claude Code session wears a ring around its icon that shows how full its context window is; it turns amber with the percent from 80%, so you know a session is about to compact before it does. Under its time, each Claude Code card shows what the session has cost so far at API prices, its helpers included.

Running a dozen? Past eight, the list shows whoever needs you first, then the busiest, then the most recent, and counts the rest by tool with Show all; idle sessions fold into one line. In the office each tool keeps up to eight seats, with the rest counted on its label.

Say yes without leaving what you're doing

When Claude Code or Copilot CLI asks to run something, the notch opens with who's asking, in which project, and the exact command. Deny and Allow sit side by side; "Always allow", with its rule in view, is a quiet link underneath, so you choose it on purpose. With the pointer over the card, Return allows, A always allows and Esc denies. Visor only takes the keyboard while the pointer is there, so your typing never goes astray. "Always" is named after the real command, so you know exactly what you're agreeing to, and a rule for ls never sneaks ls; rm -rf build through.

Claude Code and Copilot CLI. Copilot's "Always" rules are kept per project.

See what it did while you were away

An agent finishes and the notch shows its mark with a green check. Open the notch while the check is there and you get the turn in one card: how long it took, how many files it changed, lines added and removed, how many commands it ran, and whether its tests passed or failed, read from the test run's own output. The first few files are listed by name.

Open in Terminal takes you back to the agent; View diff opens a git diff of those files, new ones included, in your text editor. Visor counts it all from the events it already gets, so there's nothing to set up, and the card never replaces a panel you already had open.

Any agent Visor hears from.

See its helpers

Big jobs make Claude Code split the work: it starts subagents to search the code, write tests or review, and waits on them. Before, its card just said "Thinking" while they did all the work out of sight.

Now the card says "Waiting on 2 helpers" and gets a small ⑂ button with how many it started. Click it and the list opens under the cards: each helper's task, its type and what it's doing right now, with a turning arc while it works and a green dot when it's done. Working ones come first; past six, the rest fold into "+n more", so a busy agent never stretches the panel. Finished helpers clear when you send the next prompt.

Claude Code's subagents (the Task tool), foreground or background.

Two agents, one file

Run a few agents in the same project and sooner or later two of them rewrite the same file, each undoing the other. Visor notices when two sessions change the same file (edits and writes, not reads) within ten minutes.

The closed notch peeks with both agents' marks around an orange ⇄ and "same file". Open it and the Agents tab names the file in a banner, and both cards get an orange outline with "⇄ Copilot CLI too", so you know whom to stop. It clears itself after ten quiet minutes, or dismiss it with ✕.

Across agents and tools: Claude Code against Copilot CLI too.

Know when an agent is going in circles New in 0.11

Sometimes an agent runs the same failing test again and again, or the same command with no edit in between, and gets nowhere. Visor counts each session's calls, its helpers' too, and notices: the same call failing three times in a row, or run four times without an edit and without passing.

The closed notch peeks once with the agent's mark and "failed 3x". Open it and a Stuck? card names the command and its last error, with Ignore and Open, and the session's card gets a red outline. It clears itself once the call passes, the agent edits a file or tries something else, or you send a new prompt.

Claude Code, Copilot CLI and Antigravity CLI.

Hand off before Claude runs out New in 0.11

Deep in a task and about to hit your Claude limit? When a limit will run out within the hour at your pace, the Agents tab shows a card: when it runs out, when it resets, and how much room your other agents have left.

Copy handoff puts a short note on the clipboard for an agent with room: the project, the task, the files touched and the last test result. Paste it there and carry on. The note never holds commands, and clipboard history skips it. The closed notch peeks once per limit, and the card clears itself on a reset, when your pace recovers or once another agent takes over.

Claude Code's limits, handed to any other agent you use.

Codex, Gemini and OpenCode too

Using more than one tool? Codex CLI, Gemini CLI and OpenCode sessions now show up in the Agents tab beside the rest, with what each is doing now and which are done.

Visor reads them from the tools' own files, so there is nothing to install. That also means no approvals: those tools keep asking in their own terminal.

Codex CLI, Gemini CLI and OpenCode, beside Claude Code, Copilot CLI and Antigravity.

Every MCP server, at a glance

A line under the sessions says how many MCP servers your agents use, and what went wrong: "MCP 4 · figma failed 3x in web-shop". Click it for the full list.

Each server shows which agents use it, its recent state and the tools it was called for. Visor reads the names from your agents' own config files and the counts from their hooks, so no server is ever contacted.

Or watch them work

Prefer to see your agents at work? Switch the Agents tab to the office. Each tool gets a table and each session a little person sitting at it. They get up and walk to the terminal to run a command, the bookshelf to read, the hologram to search the web, and the break corner when a turn is done, to play darts, ping-pong, holochess or poker. When one needs you, it comes to your desk and waves, with an amber "!" or a blue "?".

It's a cozy studio at night: lamps on the tables, a wooden floor, plants in the corners. The palette button opens a picker that switches it to Galaxy (a hangar with Star Wars characters) or Starfleet (a starship deck with Star Trek characters). A little bar over each head shows how full its context is, amber when it's about to compact, and whoever waits at your desk shows how long. Hover anyone for what they're doing, how long, and what you last asked; click to jump to their terminal. Add a tool and it gets its own table. It's all Core Animation, so it costs nothing while the notch is closed.

Every agent Visor sees, in one room.

Usage

How much of each plan is left, when it runs out, and whether the provider is having a bad day.

Know you'll run out before you do

The Usage tab already shows every plan you're on: Claude's session and weekly limits, Copilot premium requests on each GitHub account (company ones too), Antigravity's model limits and OpenCode Go. Now each limit also watches how fast you're going. "On pace" means you'll make it to the reset. "Runs out in ~1h 15m" means it's time to slow down.

And when a limit will run out within the hour, the closed notch swaps its percent for the time left, so you see it coming without looking for it.

When a Claude or OpenCode Go limit you'd run out of comes back, the notch opens for a few seconds to say so, with when it ran out and when it resets next. No more checking every ten minutes to see if you can get back to work.

Claude, Copilot, Antigravity and OpenCode Go. Your own sign-ins, nothing new to log in to.

Know when it's them, not you

Agents slow, commands failing, and you start doubting your own setup. Visor reads the public status pages for the tools you've connected (status.claude.com for Claude Code and the Claude API, githubstatus.com for Copilot) every five minutes, off the main thread.

A new incident peeks once: a red dot for a major one, amber for minor, and "Claude is having issues". While it lasts, the tool's mark in the closed notch carries a small dot, and Usage puts a line under its heading with what's wrong, since when, and a link to the status page. Planned maintenance stays quiet.

Claude Code, the Claude API and Copilot. Only the tools you use.

Know when your tools have an update

Visor checks every six hours whether Claude Code, Copilot CLI, Codex CLI, Gemini CLI or OpenCode has a newer release. A peek shows once, and a What's new card with the top changes waits in Usage until you dismiss it.

Press Update and Visor runs the tool's own update command in a new Terminal window, where you see it run. Nothing changes until you press the button. Only the tools you have are checked, from their public release feeds, with no sign-in.

Every token, counted

How much have your agents actually read and written? Flip the switch at the top of the Usage tab to Tokens: every token you've used across Claude Code, Copilot CLI, Antigravity, OpenCode, Codex and Gemini CLI, by model, a little like tokscale in your notch.

The headline counts everything, and beside it the tokens without cache reads, the conversation each agent re-reads from cache on every reply: cheap, and usually most of the total. A stacked bar for each day shows which models did the work, and Overview, Models, Daily and Tools pages break it down for the last week, month or all time.

Your tools clean up after themselves (Claude Code deletes transcripts after a month), so Visor keeps its own daily totals. "All time" keeps counting.

Read from each tool's own logs on your Mac. Codex and Gemini CLI too.

Plugins

Your own panels, in a few lines of Lua.

Bring your own: plugins

Want the notch to watch something Visor doesn't? Write a plugin: a few lines of Lua in a folder. It gets its own section in the new Plugins tab, a badge on the closed notch while something needs you, and a peek when something happens. Visor draws it all, so plugins look like the rest of the notch and can't slow it down.

The first one ships with Visor: GitHub. It watches GitHub Actions on exactly the branches your agents are working on, with nothing to set up, and lists the pull requests waiting for your review. When a build breaks, the notch shows a red badge and tells you once. It works with github.com and GitHub Enterprise through your gh sign-in.

Lua 5.4, sandboxed: only the sites a plugin names, sign-ins only through gh, 1Password or the Keychain, no files, no programs. Writing Visor plugins has the whole API.

A plugin is a plugin.json and a main.lua. This one checks a build every two minutes; a check that finds nothing new is free:

visor.every(120, function()
  local r = visor.http.get("https://api.github.com/repos/octocat/visor/actions/runs?per_page=1",
                           { auth = "token", auth_host = "github.com" })
  local run = r.json.workflow_runs[1]
  visor.panel({ { title = "Actions", rows = {
    { title = run.name, status = run.conclusion or run.status, url = run.html_url, time = run.updated_at } } } })
  visor.badge(run.conclusion == "failure" and { icon = "xmark.octagon.fill", state = "bad" } or nil)
end)

What else is new

Small things that add up, since Visor 0.4.

  • Stuck? Visor says so

    When an agent repeats the same failing call, the notch peeks "failed 3x" and the Agents tab shows the command and its last error, with Ignore and Open.

  • Hand off before the limit

    When a Claude limit runs out within the hour, a card shows which agents have room and copies a handoff note for one of them.

  • What a session costs

    Each Claude Code card shows its cost so far at API prices, helpers included. Models without a price show tokens instead.

  • A context ring you can trust

    The ring now updates as soon as you send a prompt, after a compact and after a restart, and spots a 1M window from a compact that began above 200k.

  • Hello at every launch

    The intro now plays each time Visor starts. After the first welcome, it's a short hello: "Hi, I'm Visor" and the version under it. It closes by itself after three seconds, or on a click.

  • Approvals stay put, and leave a log

    An approval card stays until its own call is done, even while the agent's subagents keep working. Each answer is logged to ~/Library/Logs/Visor/approvals.log: agent, project folder, tool and outcome, never the command.

  • Local builds say so

    A Visor you built yourself calls itself "Visor (local build)" in About and the menu, with the commit, so you never mistake it for the release.

  • Update stays readable

    While a tool updates in Terminal, its version stays in view on the radar card.

  • What your agent just did

    Open the notch during a finished turn's green check: how long it took, files changed, lines added and removed, commands run and whether its tests passed, with Open in Terminal and View diff.

  • Helpers in view

    When Claude Code starts subagents, its card says how many it waits on, and a ⑂ button lists what each one is doing.

  • Two agents, one file

    When two agents edit the same file within ten minutes, the notch peeks with both marks and "same file", and the Agents tab names the file and outlines both sessions.

  • Is it them or you?

    Incidents on the Claude and GitHub status pages peek once, put a dot on the tool's mark, and show a line in Usage with a link.

  • Always, on purpose

    The approval card is the same width as every panel: Deny and Allow in the centre, and "Always allow" a quiet link under them with its rule in view.

  • A dozen agents, still calm

    Past eight sessions the Agents list shows who needs you and the busiest and counts the rest, the office counts extra people on each table's label, and the header badge reads 9+.

  • One header, balanced around the camera

    Every panel now has the same header: Agents, Usage and Music left of the camera; Clipboard, Plugins and your agents right of it. The panel stays put as you switch tabs, and the Usage gear moved into its own bar.

  • Now Playing, snug around the camera

    Music gets a narrow panel, just wide enough for the header, with the artwork beside the title and controls.

  • Room between tools

    In the Usage tab, each tool gets more space before the next, so Claude, Copilot, Antigravity and OpenCode each read as their own group, headed by their mark and name.

  • Pin from the clipboard

    Hover an item for a pin next to ✕. Pinned items keep a small green pin and survive Clear and the 200-item / 30-day cleanup. Hovering down the list is smoother too.

  • Copilot from your editor, no gh needed

    Signed in to Copilot in JetBrains, Neovim or Xcode? The Usage tab now reads that sign-in, so you no longer need to install gh and log in. (VS Code keeps its sign-in to itself, so VS Code-only users still need gh auth login.)

  • Your tools, in your order

    Drag a tool by its handle under Connected accounts (the gear on Usage) to move it up or down. The Usage tab and the closed notch follow.

  • Says why Copilot is missing

    When an account can't be read, Connected accounts now says why, per account: no sign-in found, GitHub refused it, or GitHub couldn't be reached. Plans without premium requests, like Copilot Free, show their chat and completions limits.

  • Only the tools you have

    Tools that aren't on your Mac stay out of the Usage tab and the notch. With only Copilot or Antigravity, the limits use the whole width.

  • Play means play, even in a background tab

    Dia freezes background tabs, so pressing play in the notch used to stay silent until you opened the YouTube tab. Now Visor shows the tab for a moment until the sound starts, then puts you back where you were.

  • Switch Copilot accounts, no restart

    Change the active account with gh auth switch or in Copilot CLI and the Usage tab follows within two minutes, or at once when you open it.

  • About Visor

    The menu bar menu now opens an About panel with the version, and links to this site, GitHub and a new issue.

  • No more "playing" in silence

    A YouTube tab the browser hadn't loaded yet no longer shows as playing in the notch.

  • Done, with a check on top

    A finished turn now shows the agent's mark with a small green check, just like the "?" and "!" badges. The project and how long it took are on hover.

  • Agents remember where they were

    Visor used to forget your running sessions when it restarted, so the list said "No agents running" until each one did something. Now they're right where you left them.

  • Your plan, as it is today

    Upgraded from Pro to Max? The plan name now comes from your account, not from when Claude Code last signed in.

  • "Waiting for your reply" only when it is

    An agent that finishes with a plain answer no longer shows a blue "?" a minute later. Only a turn that ended with a question does.

  • The same breathing room everywhere

    Every icon in the closed notch sits the same distance from the notch and from the edge, whatever it shows. Music next to busy agents is now a small badge on the artwork.

  • One switch for approvals

    Approvals in the Notch in the menu now covers Claude Code and Copilot CLI alike. Turn it off and each agent asks in its own terminal. Agents are ticks in the menu, so each connects on its own.

  • A cleaner close

    Moving away quickly could leave a line of text hanging below the notch for a moment. Not anymore.

Make yourself at home

Visor isn't from the App Store, so macOS asks you to approve it once. Here's every prompt you'll see, in order.

  1. Install with Homebrew

    brew install --cask tailamphat/tap/visor

    Already have it? From 0.7.0 Visor updates itself: it downloads new versions in the background and installs them when it restarts (or pick Restart to Update in its menu). On an older version, run brew update && brew upgrade --cask visor once.

  2. Let macOS open it

    Homebrew clears the download flag for you, so Visor usually just opens. If macOS says Apple could not verify it:

    1. Click Done (not Move to Trash).
    2. Open System Settings → Privacy & Security and scroll to Security.
    3. Next to "Visor was blocked to protect your Mac", click Open Anyway, enter your password, then Open.

    If it says Visor "is damaged", remove the download flag in Terminal and open it again:

    xattr -dr com.apple.quarantine /Applications/Visor.app

  3. Connect your agents

    Hover the notch and choose Connect your agents (or tick it under Agents in the menu bar icon). Visor adds its hook to Claude Code, Copilot CLI and Antigravity so the notch hears what they do. Untick it there to disconnect before uninstalling. Approvals in the Notch in the same menu sends approvals back to the terminal.

  4. Say yes to the permissions, when they come up

    • Accessibility, for pasting from the clipboard and the media keys: System Settings → Privacy & Security → Accessibility, turn on Visor.
    • Automation, for play, pause and skip: click Allow when macOS asks if Visor may control Spotify, Music or your browser.
    • Keychain, for the sign-ins your AI tools already saved: if macOS asks whether security may use "Claude Code-credentials" or "copilot-cli", click Always Allow.

  5. Music in any browser (optional)

    Choose Browser Extension for Music… in the menu bar icon. Visor shows the extension's folder and how to add it: in Chrome, Dia, Arc, Brave or Edge, turn on Developer mode under Extensions and choose Load unpacked; in Firefox or Zen, open about:debugging and choose Load Temporary Add-on.

  6. Hover the notch

    Usage fills in from the tools you're signed in to. If one is missing, the gear on the Usage tab says why, with one button to fix it.

Turned something down by mistake? Every permission can be changed in System Settings → Privacy & Security. Uninstall with brew uninstall --cask visor.

Your data stays on your Mac

Visor has no server of its own, no account and no analytics.
