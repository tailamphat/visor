Visor design system

Every colour, text size, corner, fill, gap and shared component that Visor's notch draws with, live on the notch's black. Pick a tint at the top to recolour the components, try their states, and copy the SwiftUI or plugin code next to each.

The values on this page are read from blocks that scripts/site-tokens.sh generates from Sources/VisorCore/DesignTokens.swift, DesignComponents.swift and Plugins/PluginDesign.swift; scripts/check.sh fails when they drift. Plugin authors: see the plugin guide.

Colour

Theme.* / DS.Palette.* / var(--v-*)

Tuned for the notch's pure black. Views use Theme; the approval and intro colours that Theme doesn't name are on DS.Palette. A tag marks the names a plugin may use (color =, tint =). Click a swatch to copy its CSS variable.

Shadow

.dsShadow(_:)

Black at a strength, blurred by a radius, moved down by y. Shown on a grey ground so the black reads; the browser's blur is close to, not exactly, SwiftUI's.

Rules

each says whether scripts/check.sh checks it

Pick from the system, never type a value checked

No literal colour, text size, radius or fill in an app view. scripts/check.sh fails on one (rule 5, patterns in scripts/design-literals.txt); there is no allowlist of lines, only Office pixel art and agent brand marks are skipped. Spacing and padding numbers are not checked: use DS.Space anyway.

Don't
Text(title)
    .font(.system(size: 10.5, weight: .semibold))
    .foregroundStyle(Color(hex: 0x3987E5))
RoundedRectangle(cornerRadius: 7)
    .fill(Color.white.opacity(0.1))
Do
Text(title)
    .font(DS.font(.sm, .semibold))
    .foregroundStyle(Theme.accent)
RoundedRectangle(cornerRadius: DS.Radius.sm, style: .continuous)
    .fill(DS.Fill.subtle)

Use the shared component, not your own chrome not checked

A button, badge, banner or section title in a card is the shared one, so every tab looks the same. No script catches a hand-made one built from tokens: review does.

Don't
hand-made: 20 pt, radius 7, 11.5 pt, its own blue
Do
CardButton(.primary)

The website uses the variables checked

Site and document CSS use var(--v-*); an added raw hex equal to a palette token fails scripts/check.sh (rule 4). After changing a token or a component measure, run scripts/site-tokens.sh --write and scripts/site-tokens.sh --write docs/design-system.html.

Don't
.chip { background: #3987E5; }
Do
.chip { background: var(--v-accent); }

Plugins pick by name not checked

Plugins use palette names and type steps, never a hex or points. Nothing checks a plugin's source: a name Visor doesn't know is ignored and the piece keeps its default look, so a typo never breaks a view.

Don't
ui.text { "Deploys", color = "#3987E5", size = 13.5 }
Do
ui.text { "Deploys", color = "accent", size = "lg", weight = "semibold" }

Adding a value tests and check.sh catch parts

A new token: one public static let name: Type = literal line in its group of DesignTokens.swift (the generator reads the file as text), plus DesignScale.all. A component measure: DesignComponents.swift and its measurements list (a test checks each sits on its scale). Then regenerate both pages (scripts/check.sh fails while one is stale). Anything beside the camera stays balanced: the same inset left and right (not checked by a script).
